# ADR-0007. Тестовая стратегия: unit на домене, testcontainers на реальных зависимостях

**Статус:** принято

## Контекст

Нужно доверять поведению, завязанному на реальную инфраструктуру:
DB-констрейнты (`RACE-001`), атомарность транзакций (outbox), реальную
доставку в Kafka. Два очевидных полюса: мокать БД/Kafka везде (быстро, но
рискует не поймать реальные баги) или держать общий shared dev-стенд для
тестов (медленно и хрупко в CI).

## Решение

Два уровня:

1. **Unit** — на чистом домене (`internal/core/domain`, `internal/core/application`),
   без I/O вообще: `fake<Port>` вручную написанные заглушки интерфейсов
   (`docs/style.md`), без БД, без сети.
2. **Integration** (`//go:build integration`) — **реальные** Postgres и Kafka
   через `testcontainers-go`, поднимаются и убиваются автоматически на
   каждый прогон. Один Postgres-контейнер на весь пакет через `TestMain`
   (не по контейнеру на сьют) — конкретное ускорение: ~30-35с → ~13.5с.

## Альтернативы

**Мокать БД/Kafka и в "интеграционных" тестах тоже.** Отклонено — это
убивает саму цель интеграционных тестов. Конкретные реальные баги, пойманные
именно потому, что тест бил в настоящий Postgres, а не мок: маппинг
`SQLSTATE 23505` на `ErrConcurrentReservation` (мок никогда не вернёт
реальный код ошибки Postgres), и баг сканирования `uuid.UUID` в
`FindFreeCopyID` (через поле структуры gorm-конвертер отрабатывает, через
голую переменную — нет; мок этого различия просто не воспроизведёт).

**Общий персистентный dev-стенд (`docker-compose up` один раз, тесты бьют в
него руками).** Отклонено: состояние утекает между прогонами тестов, если не
следить за truncate вручную; в CI требует отдельного шага поднятия
окружения. `testcontainers` даёт ту же гарантию изоляции (свежее окружение
на прогон) без этой операционной возни — контейнер стартует и гасится
автоматически внутри самого теста.

**Отдельный контейнер на каждый test suite (было изначально).** Заменено на
один общий контейнер на пакет через `TestMain` — старт контейнера
доминировал в общем времени прогона; после объединения суммарное время
упало примерно втрое.

## Последствия

- Общий контейнер на пакет требует дисциплины в изоляции: `TRUNCATE` всех
  таблиц в `SetupTest` между тестами — один раз забыли добавить `outbox` в
  список после того, как появилась миграция `00003_outbox.sql`, что привело
  бы к утечке состояния между сьютами; поймано и исправлено, теперь входит
  в чек-лист при добавлении новой таблицы.
- `testcontainers-go` — стороння зависимость с собственными багами:
  версия `v0.44.0` ловила ложный `rootless Docker is not supported on
  Windows` — зафиксирована версия `v0.43.0` для обоих модулей
  (`testcontainers-go` и `.../modules/kafka`) как обходной путь.
- Consumer-тесты (`KAFKA-003`) потребуют дополнительной изоляции —
  уникальный consumer group ID и/или топик на тест, иначе тесты в одном
  сьюте видят чужие сообщения через общий брокер (см. обсуждение
  `OffsetOldest` в `outbox_worker_test.go`).
