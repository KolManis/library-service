# ADR-0006. Списание книги (внешнее событие) vs списание копии (внутренняя команда)

**Статус:** принято

## Контекст

Изначально в `DESIGN.md` был только один сценарий списания — `KAFKA-003`:
консьюмер `book.decommissioned` списывает **все** копии книги разом. Разбирая
его, возник вопрос: а что если нужно списать **одну конкретную** копию
(потеряна, повреждена), не всю книгу целиком? Это оказался другой по природе
сценарий, не просто частный случай первого.

## Решение

Разделили на две отдельные фичи, использующие один и тот же доменный
примитив (`Loan.Cancel()`, ADR-0005):

| | `COPY-001` | `KAFKA-003` |
|---|---|---|
| Инициатор | Библиотекарь, внутри сервиса | Внешняя система (гипотетический каталог книг) |
| Транспорт | Синхронная HTTP-команда, `POST /copies/{id}/decommission` | Асинхронное событие Kafka, `book.decommissioned` |
| Область действия | Одна `Copy` | Все `Copy` данной `Book` |
| Побочный эффект | Отменяет `reserved`-бронь именно на эту копию | Отменяет `reserved`-брони на всех копиях книги |

`COPY-001` реализован первым — он проще (без Kafka/testcontainers) и вводит
`Loan.Cancelled`, который `KAFKA-003` затем переиспользует, а не дублирует.

## Альтернативы

**Один сценарий на всё — консьюмер `book.decommissioned`, списание одной
копии эмулировать книгой с одной копией.** Отклонено: два сценария имеют
разную природу инициатора (внутреннее решение библиотекаря vs внешнее
событие) и разный транспорт (синхронный HTTP vs асинхронный Kafka) — сводить
их в один API исказило бы оба: HTTP-ручка не должна тянуть за собой
Kafka-инфраструктуру ради тривиального "списать один экземпляр".

**Только `book.decommissioned`, без отдельной ручки для одной копии.**
Отклонено — реальный библиотечный кейс "экземпляр потерян/повреждён" не
подразумевает списания всей книги с оборота, это разные по частоте и по
смыслу операции.

**Общий HTTP-эндпоинт с опциональным `book_id`/`copy_id` в теле запроса.**
Рассматривалось, отклонено: смешивает синхронный (HTTP) и асинхронный
(Kafka-событие извне) триггеры в одной ручке — событие `book.decommissioned`
по определению не приходит через HTTP этого сервиса, у него нет вызывающего
клиента, которому можно отдать HTTP-ответ.

## Последствия

- `Loan.Cancel()` вызывается из двух разных мест (`decommissioncopy.Handler`
  и будущего `book_decommissioned_consumer.go`), но определён и протестирован
  один раз в домене.
- `ICopyRepository`/`ILoanRepository` получили по одному новому методу
  каждый (`DecommissionByID`, `FindReservedByCopyID`), переиспользуемому в
  обеих фичах через параметризацию по `copyID`/`bookID` на уровне запроса,
  а не через дублирование методов.
- `KAFKA-003` явно не реализует продюсер `book.decommissioned` — по контракту
  это внешнее событие, издатель которого лежит вне границ этого сервиса.
