# ADR-0008. Fine создаётся application-слоем, а не доменом Loan

**Статус:** принято

## Контекст

Правило «возврат книги из статуса `overdue` создаёт штраф» затрагивает два
разных агрегата — `Loan` (меняет статус) и `Fine` (новая сущность). Нужно
решить, где живёт эта координация: внутри `Loan.Return()`, или снаружи.

## Решение

`Loan.Return(now)` только переводит статус, ничего не знает про `Fine`.
Координацию делает `returnloan`-хендлер (application-слой): запомнить статус
**до** возврата → вызвать `l.Return(now)` → если был `overdue`, создать
`Fine` через `IFineRepository` — обе записи в одной транзакции
(`ITransactor`). Аналогичный принцип для будущего воркера штрафов:
`create-fines` координирует `Loan.MarkOverdue()` и создание `Fine`, а не
`Loan` сам.

## Альтернативы

**Создавать `Fine` внутри `Loan.Return()`.** Отклонено: `Loan` и `Fine` —
разные агрегаты с разным жизненным циклом. Если `Return()` начнёт создавать
`Fine`, домен `loan` должен будет знать о существовании чужого агрегата — а
дальше встаёт вопрос "кто его сохранит", на который у домена нет ответа: он
не видит репозитории, это не его забота (ADR-0001, зависимости только
внутрь).

**Доменное событие `LoanReturned` с обработчиком, создающим `Fine`.**
Формально честная альтернатива (событие как способ развязать агрегаты), но
для **синхронного** правила "возврат ⇒ штраф в той же операции" — лишний
уровень косвенности. События (`PullEvents`/outbox, ADR-0003) оставлены для
интеграции **наружу** системы (Kafka), а не для связи двух агрегатов внутри
одной транзакции одного и того же запроса.

## Последствия

- Application-слой явно координирует несколько агрегатов — ровно то, для
  чего он существует (оркестрация без бизнес-правил внутри себя: правило
  "overdue → есть штраф" не в хендлере, оно проверяется через факт "статус
  ДО возврата был overdue", а саму сумму считает `Fine` (см. формулу — она
  собственное бизнес-правило домена `Fine`, а не application-слоя).
- `command_handler_test.go` для `returnloan` тестирует оба агрегата разом
  (создание `Loan` в статусе `overdue`, вызов `Handle`, проверка что и
  `Loan.Update`, и `Fine.Create` были вызваны) — это осознанно, координация
  агрегатов и есть то, что тестируется на этом уровне.
