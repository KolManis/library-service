# ADR-0005. Loan.Cancelled — отмена только из reserved, не из issued

**Статус:** принято

## Контекст

Копия (или вся книга) может быть списана, пока на неё есть активная `Loan`.
Нужно решить, что происходит с этой `Loan` в момент списания — в частности,
можно ли "отменить" выдачу, если книга уже физически на руках у читателя
(`status = issued`).

## Решение

Новый терминальный статус `StatusCancelled`. Переход разрешён **только** из
`reserved`:

```go
StatusReserved: {StatusIssued, StatusExpired, StatusCancelled},
StatusIssued:   {StatusReturned, StatusOverdue}, // Cancelled сюда не входит
```

`Loan.Cancel(now)` не проверяет TTL (в отличие от `Expire`) — решение об
отмене приходит **извне** (списание), а не потому что истекло время, поэтому
по форме ближе к `Return`, чем к `Expire`.

Если на момент списания `Loan` в статусе `issued` — она вообще не трогается.
Читатель возвращает книгу штатным `Return`; `Return()` не проверяет
`Copy.decommissioned` никак (см. ADR-0002) — копия просто перестаёт
предлагаться `FindFreeCopyID` после того, как последний раз вернётся.

## Альтернативы

**Разрешить `Cancel` и из `issued`, силой "забрать" книгу.** Отклонено:
физически невозможно — книга реально у читателя дома, статус в БД не может
отражать то, что не соответствует реальности. Насильно проставленный
`cancelled` на `issued`-выдаче — это ложь в данных, не отмена.

**Отдельный статус для "issued, но копия уже списана".** Рассматривалось —
избыточно: `Copy.decommissioned` уже независимый флаг (ADR-0002), которого
достаточно, чтобы копия больше не предлагалась. Заводить ещё один статус
специально под этот пересекающийся случай дублирует информацию, которая уже
выражена комбинацией `Loan.status` + `Copy.decommissioned`.

**Не проверять статус в самом `Cancel()`, полагаться на то, что вызывающий
код (`FindReservedByCopyID`) и так возвращает только `reserved`-брони.**
Отклонено — это defense in depth: если по ошибке (баг в другом месте,
рефакторинг) в `Cancel()` попадёт `issued`-`Loan`, метод обязан сам отказать
(`ErrInvalidTransition`), а не молча сломать данные, полагаясь на то, что
вызывающий код всегда прав.

## Последствия

- `Cancel()` переиспользует `ErrInvalidTransition` — отдельной ошибки под
  этот кейс не заводили, семантика та же, что у любого другого запрещённого
  перехода.
- Общий примитив для двух фич: `COPY-001` (списание одной копии, синхронная
  команда) и `KAFKA-003` (списание книги целиком, консьюмер) — обе вызывают
  один и тот же `Cancel()`, логика не дублируется (см. ADR-0006).
