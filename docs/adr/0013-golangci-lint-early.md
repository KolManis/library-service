# ADR-0013. golangci-lint v2 с расширенным набором линтеров — раньше, а не потом

**Статус:** принято

## Контекст

На момент решения (`INFRA-EARLY-001`) в проекте уже был стандартный набор
линтеров golangci-lint (`errcheck`/`gosimple`/`govet`/`ineffassign`/
`staticcheck`/`unused` — дефолт). Вопрос — заводить ли расширенный набор
(`errorlint`, `contextcheck`, `sqlclosecheck`, `forbidigo`) сейчас, когда
кодовая база маленькая, или отложить до момента, когда реально понадобится.

## Решение

Настроено сейчас, до `KAFKA-001`/`002`/`003`:

- `errorlint` — правильная работа с обёрнутыми ошибками (`errors.Is`/`As`),
  критично для проекта, где вся доменная модель ошибок построена на
  sentinel-переменных и `%w` (`ADR-0009`).
- `contextcheck` — согласованная передача `context.Context`, особенно важно
  там, где транзакции (`ITransactor`) и graceful shutdown зависят от того,
  что контекст передаётся правильно, а не создаётся заново по пути.
- `sqlclosecheck` — незакрытые ресурсы (`sql.Rows`, Kafka-консьюмеры/
  продюсеры) — линтер актуален именно с появлением Kafka-клиентов, которые
  держат сетевые соединения.
- `forbidigo` — запрет голого `log.*` (см. ADR-0012), инвариант в коде
  вместо устной договорённости.

## Альтернативы

**Только дефолтный набор линтеров.** Отклонено как недостаточное именно для
инвариантов, которые важны в этом проекте: `errorlint` и `contextcheck`
проверяют ровно те два паттерна (обёрнутые sentinel-ошибки,
контекст-based транзакции), на которых держится вся архитектура — их
нарушение не поймать дефолтным набором.

**Добавить правила задним числом, когда кодовая база вырастет.** Отклонено
явно, с расчётом (тот же, что в ADR-0012): мигрировать 5-6 вызовов `log.*`
и несколько мест работы с контекстом — дёшево сейчас, дороже после
появления воркеров/консьюмера/продюсера, где таких мест станет в разы
больше.

## Последствия

- Конфиг `.golangci.yml` — схема v2 (`linters.settings.<linter>` вложенно,
  не отдельный верхнеуровневый `linters-settings:` — это синтаксис v1,
  ловили один раз по ошибке при первой настройке, поправлено).
- Полный `golangci-lint run` проверен вживую на `0 issues` при каждом
  значимом коммите этого проекта — не разовая настройка, а часть definition
  of done (`CLAUDE.md`).
- CI линтит и `test/integration/*.go` (файлы за `//go:build integration`)
  только после добавления `--build-tags=integration` в шаг
  `golangci-lint-action` — по умолчанию action их не видит, что было
  найдено и исправлено отдельно.
