# ADR-0015. Мягкое удаление книги (`archived`) вместо физического

**Статус:** принято

## Контекст

Каталогу нужна операция «убрать книгу» (в рамках будущего `BOOK-CRUD-001`).
Физическое удаление упирается в внешние ключи — цепочка в схеме такая:

```
books ←── copies.book_id ←── loans.copy_id ←── fines.loan_id
```

Ни один FK не объявлен с `ON DELETE`, то есть действует `NO ACTION`:
`DELETE FROM books` будет **отвергнут** Postgres, если у книги есть хоть один
экземпляр. Продавить можно только через `ON DELETE CASCADE` — и тогда каскад
пойдёт по всей цепочке.

## Решение

Флаг `archived boolean NOT NULL DEFAULT false` на `books`, по образцу уже
существующего `copies.decommissioned` (ADR-0002). Удаление книги = простановка
флага. Строка остаётся в БД навсегда.

Архивная книга:
- не попадает в каталог, поиск и выдачу новых броней;
- остаётся резолвимой по `id` — история выдач продолжает показывать, что
  именно читатель брал.

Экземпляры архивной книги не трогаются отдельно: новых броней на них не будет,
потому что книга не видна, а уже выданные доживают штатно и возвращаются
обычным `Return` — та же логика, что при списании (ADR-0005, ADR-0006).

## Альтернативы

**Физическое `DELETE` + `ON DELETE CASCADE`.** Отклонено: каскад снёс бы не
карточку книги, а всю связанную историю — копии, выдачи и **штрафы**. Штраф
это денежное обязательство; его исчезновение вместе с правкой каталога
недопустимо ни при каких обстоятельствах.

**Физическое `DELETE` с запретом при наличии копий** (то, что БД делает и так
по умолчанию). Отклонено: удалить будет нельзя ровно те книги, которые и
хотят убирать — те, что реально были в фонде. Удалению поддадутся только
ошибочно заведённые пустышки без единого экземпляра. Это не решает исходную
задачу.

**Снапшот названия и автора в `loans`.** Отклонено как решение *этой* задачи:
снапшот защищает от **изменения** данных, а не от их удаления — от удаления
защищает как раз мягкое удаление. Кроме того, для библиотеки исправленное
название в старой истории скорее желательно: книга физически та же самая, в
отличие от цены в заказе интернет-магазина, которая задним числом меняться не
имеет права. Если когда-нибудь появится требование «история не меняется
задним числом» — это отдельное решение и отдельный ADR.

## Последствия

- В схеме появляется ещё один флаг-состояние, и **все** выборки каталога
  обязаны его фильтровать — ровно как `FindFreeCopyID` фильтрует
  `NOT c.decommissioned`. Забытый фильтр = архивная книга всплывает в поиске.
  Это цена мягкого удаления: инвариант держится на дисциплине запросов, а не
  на отсутствии строки.
- Строки `books` накапливаются и физически не удаляются никогда. Для
  библиотечного каталога объёмы пренебрежимы.
- `DELETE /books/{id}` семантически становится «архивировать». Это
  распространённая практика, но если захочется честности в именовании —
  альтернатива `POST /books/{id}/archive`, по образцу уже существующего
  `POST /copies/{id}/decommission`. Выбор формы ручки оставлен на момент
  реализации `BOOK-CRUD-001`.
