# Architecture Decision Records

Каждый файл фиксирует **одно** архитектурное решение: контекст, выбор,
рассмотренные альтернативы и последствия.

Правила ведения:

- ADR не переписывается после принятия. Если решение изменилось — пишется
  новый ADR со статусом «заменяет ADR-XXXX», а старый получает «заменён
  ADR-YYYY».
- Нумерация сквозная, порядок — хронологический.
- Раздел «Альтернативы» обязателен: решение без отвергнутых вариантов — не
  решение, а единственный пришедший в голову способ.
- Для новой фичи ADR пишется **до** кода, как часть обсуждения "что и зачем
  делаем" — не задним числом после того, как код уже написан и решение забылось.
