# Style Guide

Дополнение к [../CLAUDE.md](../CLAUDE.md): конкретные технические соглашения по
коду, чтобы не изобретать заново в каждом PR и не расходиться по мелочам. Правила
ниже — не абстрактная теория, а фиксация того, что уже само сложилось в более
поздних файлах проекта (`returnloan`, `return_handler.go`), и приведение более
ранних файлов (`reservecopy`, `issueloan`, `reserve_handler.go`) к тому же виду.

## Комментарии

**Каждый экспортируемый идентификатор** (функция, метод, тип, константа) —
godoc-комментарий: начинается с самого имени, коротко что делает и что
возвращает, если это не тривиально из сигнатуры. Формат — стандартный для Go
(`go doc`, подсказки IDE при наведении, `golint`/`revive` ожидают ровно это):

```go
// Handle возвращает все выдачи читателя по readerID. Пустой список — не ошибка.
func (h *Handler) Handle(ctx context.Context, q Query) ([]ports.LoanView, error)
```

Даже для `internal/`-пакетов, которые нельзя импортировать из другого модуля —
`go doc ./...` и IDE это всё равно показывают внутри репозитория, польза не
только для внешних потребителей.

Приватные (с маленькой буквы) идентификаторы — как раньше, без комментария, если
не несут то, чего нет в сигнатуре. Тривиальные однострочные геттеры (`ID()`,
`Status()` и т.п.) — минимальный однострочник, не нужно расписывать очевидное.

Комментарий сверх стандартного godoc-описания пишем, когда он несёт то, чего нет
в самой сигнатуре:

- **Non-obvious workaround** — например, `FindFreeCopyID` в `copy_repository.go`
  объясняет, зачем сканировать в структуру, а не в голый `uuid.UUID` (иначе gorm
  не сработает так, как ожидается) — это не «что», а «почему именно так, а не
  очевидным способом».
- **Скрытый механизм** — `dbFromContext`/`WithinTransaction` в `transactor.go`
  объясняют, как транзакция попадает из контекста в репозиторий — по коду одной
  функции это не считывается, нужно видеть связь между двумя файлами.
- **Инвариант, на который код полагается неявно** — например, комментарий в
  `returnloan/command_handler.go` про то, почему `*l.DueAt()` разыменовывается
  без nil-проверки (домен уже гарантирует непустоту через `MarkOverdue`).
- **Комментарии-нумерация шагов внутри функции с несколькими последовательными
  действиями** (оркестрация в command-хендлерах: «достать → вызвать домен →
  сохранить») — допустимы и полезны, формат `// N. текст`, без слова «Шаг».

Такие «почему»-комментарии — дополнение к обязательному godoc, не замена ему.

## Импорты

Два блока, разделённых пустой строкой: сначала стандартная библиотека, затем всё
остальное одним алфавитным блоком (свои пакеты `github.com/KolManis/...` вперемешку
с внешними зависимостями, по алфавиту). Это ровно то, что делает `gofmt`/`goimports`
сам по себе, без ручной подгонки и без `-local` флага — не разносить third-party и
внутренние пакеты по отдельным блокам вручную, лишняя договорённость, которую
нечем поддерживать автоматически.

## Перенос параметров функции

Один параметр на строку, если параметров 3 и больше — так они читаются как
список, а не сливаются в одну простыню. При 1-2 параметрах — одна строка.
`gofmt` не переносит длинные сигнатуры сам (в Go нет ограничения на длину строки),
поэтому это ручная дисциплина, не проверяется линтером.

## Наименование

- Receiver — одна буква по первой букве типа: `r` для репозиториев, `h` для
  Handler'ов (и HTTP, и application-слоя), `l`/`f` для методов агрегатов
  (`Loan`/`Fine`). Уже соблюдается везде, держим и дальше.
- Поле в HTTP-хендлере, хранящее application-хендлер — называем по смыслу
  сценария, не общим словом `handler` (`reserve`, `issue`, `returnLoan`, `query`
  — не `handler`, `h`, `svc`).
- Fake-заглушки в тестах — `fake<ИмяПорта>` (`fakeLoanRepo` для
  `ILoanRepository`, `fakeReaderLoansReader` для `IReaderLoansReader`), не
  сокращать до общего `fakeReader`/`fakeRepo` — в пакете может позже появиться
  больше одного порта, и общее имя перестанет быть однозначным.

## Персистентные модели (`adapters/out/repositories`)

Каждая gorm-модель (`loanModel`, `fineModel`, ...) — однострочный комментарий над
типом (роль: «строка таблицы X, про бизнес-правила не знает») и над `TableName()`
(почему override — иначе gorm выведет неверное множественное число). Это не
модель-специфичный комментарий, а фиксированный шаблон, применяем ко всем моделям
одинаково.
